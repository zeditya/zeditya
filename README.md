## What I actually do

<img align="right" width="240" src="assets/iron-man-hammer.gif" alt="Building something by hand in a cave workshop" />

I build in small, finished increments. A half-built idea teaches you nothing;
an ugly finished thing teaches you everything — including where you were wrong.

- **Fundamentals** — DSA in C and C++, complexity, memory. Deliberately boring, because everything else stands on it.
- **Full stack** — HTML, CSS and JavaScript today, Ruby on Rails next. I want to know how a framework *thinks*, not just which command to run.
- **Games** — Godot 4 and GDScript. Also the best excuse I've found to write a colour-theory hack-and-slash.

## The boulder

<img align="right" width="320" src="assets/sisyphus.gif" alt="Sisyphus pushing a boulder uphill" />

Sisyphus pushes a boulder uphill forever. I work through Striver's A2Z sheet.
His boulder doesn't compile, so I'd argue I have the easier job.

Every solution gets the pattern named, the approach written down, and its time and
space complexity recorded — because past-me is not a reliable narrator. The tracker
in that repo rebuilds itself from git history, so progress is a fact, not a feeling.

## How I work

<img align="right" width="280" src="assets/lock-in.gif" alt="Leaning forward, locked in" />

- **Consistency over intensity.** Ninety focused minutes a day beats a heroic all-nighter I need a weekend to recover from.
- **Read the whole error.** The answer is usually in the part I skipped.
- **Explain it or you don't know it.** If I can't teach it to a friend, I'm still guessing.
- **Finish things.** A slightly ugly project that's deployed beats a perfect one stuck on a private branch.

No 3 a.m. genius here. Just a boring, repeatable evening session and a compiler that keeps me honest.
