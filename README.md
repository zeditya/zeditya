## The workshop

<img align="right" width="340" src="assets/iron-man-hammer.webp" alt="Building the thing by hand, in a cave, with a box of scraps" />

Four tools I reach for without opening the docs, and two I'm still earning.

- **`C`** — where I find out what the machine actually does: pointer arithmetic, `malloc`/`free` by hand, buffer overruns I caused on purpose.
- **`C++`** — STL containers and the costs hiding behind them. `vector` growth, `unordered_map` hashing, why `O(n log n)` still loses to a tight loop.
- **`Python`** — the language I prototype in, plus [a billing app for a campus food court](https://github.com/zeditya/Food_court_management_system) that taught me the gap between "it works" and "it's usable".
- **`Ruby on Rails`** — conventions I can now explain rather than obey: the request lifecycle from route to view, migrations as versioned history.
- **`Godot 4 / GDScript`** — one finished game's worth of experience: signals over polling, tuning over feature-adding.
- **`Git` + the shell** — the tools I'd be lost without, which is why I keep learning them properly instead of memorising the six commands I use.

## How I work

<img align="right" width="270" src="assets/lock-in.webp" alt="Leaning forward, locked in" />

Rules I actually follow, not rules I admire:

- **Measure before optimising.** If I can't put a number on the slowness, I'm about to make it slower.
- **Three copies before an abstraction.** Two is a coincidence, three is a pattern. Before that, a function is cheaper than a framework.
- **Reproduce, then fix.** A bug I can't trigger on demand is a bug I haven't understood yet.
- **Complexity in the comment.** Every non-obvious function states its `O()` and why, next to the code that earns it.
- **Tests outlive intentions.** Behaviour that matters gets an assertion, not a promise in a README.
- **Read the source.** Docs describe what someone meant; the source describes what happens.
- **Small commits, honest messages.** The diff says what changed; the message says why it had to.
